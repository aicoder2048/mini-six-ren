# Web 九宫旋转路径可视化实施计划

## 目标与范围

在 Web 本地起课结果中增加九宫环，按 `data/symbols.json` 的 `order` 顺时针排列九个符号，展示起算点、三个数字逐段数宫的经过位置及初传／中传／末传落点、落点五行色、两段有方向的关系和各落点的 `finger_position`／`bagua`。空状态也复用九宫环，但不伪造起课结果。

保留现有三传卡片、关系解释、文化背景、AI 面板、每页面独立控制器、`is_running` 防重入、AI 失败保留本地结果的行为。不修改 `src/hand_technique.py`、`src/utils/symbol_relations.py`、`src/symbols.py`、`data/`、CLI 或 AI prompt；不添加导出／分享／历史，不引入新依赖。

## 已核实的实现背景

- `HandTechnique.predict` 验证数字后从索引 0 开始，每段执行 `(position + number - 1) % len(SYMBOLS)`，返回 `Prediction(symbols, relations)`。第二、三段从上一段落点续数，不先前进一步。
- `Symbol` 已暴露 `order`、`finger_position`、`bagua`。当前 `SYMBOLS` 的加载顺序与 `order=1..9` 一致：大安、留连、速喜、赤口、小吉、空亡、病符、桃花、天德。展示可排序副本，绝不能原地排序／修改全局数据。
- `_perform_divination` 已获取三种模式转换后的 `numbers`，先显示本地结果再等待 AI。不得从 `input_summary` 字符串解析数字，也不得在显示时重新读取可变化的输入框。
- `_display_results` 现有五行钩子是 `transmission-card[data-element]` 和 `element-badge`；`tests/test_web_themes.py` 断言其数量与次序。九宫组件使用独立类名，避免混入这些旧查询。
- `night/ink/neon.css` 使用 `html[data-theme="..."]` 隔离样式，已有 `--el-wood/fire/earth/metal/water`；素纸基础样式没有这些五行配色。旧 `.compass` 的四字装饰及主题动画不应套到数据九宫节点上。

## 明确的路径与展示约定

1. **布局**：`order=1`（大安）在正上方；其余每隔 40° 顺时针排列。这里是项目九宫计数顺序，不是按方位或后天八卦重新排盘；包括空亡在内九个符号都放在环上。
2. **数法**：本宫算第 1 数。段起点索引为 `s`，数字为 `n`，完整计数序列为 `[(s+k)%9 for k in range(n)]`，落点为序列末项，下段从该末项开始。`n=1` 原地落宫，不移动。计数序列包括起点和落点；图例明确这一点，不把输入误当移动边数。
3. **经过标记**：每个节点固定保留三条小标记槽（初／中／末），对应段计数访问过该宫才显示标记，可附访问次数；三段重合不相互覆盖。落点另用更明显的边框／徽标写出完整“初传／中传／末传”，同宫多次落点全部保留。全局起算点大安单独标“起算”，每段起点在段摘要中写清。
4. **多圈**：输入最大 999。模型可以存储至多 2997 个计数项用于测试，UI 不创建上千节点或逐步动画。每段聚合九宫访问次数，展示 `n-1` 次移动、`(n-1)//9` 个整圈和余下移动步数；如 10 为一圈并回到原宫，9 是八步并非完整一圈。访问次数总和应为 n。
5. **颜色与方向**：五行颜色属于符号，不用五行颜色混充三段路径编号。节点／落点摘要带五行文字，路径用“初／中／末”与不同槽位区分，不能仅靠色相识别。两段关系在环组件下方紧邻的摘要中明确显示 `初传·符号 → 中传·符号 · 关系` 和 `中传·符号 → 末传·符号 · 关系`，复用传入的 `relations` 和 `describe_relation`，不另算生克，不反转“被生／被克”的主语。
6. **元数据位置**：环下固定三个落点摘要（属于同一个可视化组件），每个显示阶段、符号、五行、`手指位置：{finger_position}`、`八卦：{bagua}` 原始字符串；无需悬停或展开即可读到。环上紧凑徽标与摘要阶段名一一对应。不要纠正数据拼音等既有内容，不送入 AI。
7. **空状态**：显示相同顺序的静态九宫环与“起算”位置、顺时针说明，保留待启文案和三传阅读指引；不显示经过标记、落点或关系。

## 文件与实施步骤

### 1. `src/web.py`：纯展示模型与快照

- 引入 `SYMBOLS`，在该文件内增加小型纯函数（建议 `build_palace_walk(numbers)`）及必要的不可变 dataclass；不依赖 NiceGUI 控件或 AI。
- 返回按 `order` 排好的九宫和三段轨迹；每段包含阶段、输入数、起点索引、计数序列、九宫访问次数、落点索引、整圈／余步。索引统一指向排序后的九宫列表。复用 `validate_numbers` 约束输入，不扩展核心算法职责。
- 初始化控制器的 `number_snapshot = None`，每次新提交清理时同步重置，在输入验证成功后保存 `tuple(numbers)`。结果渲染只读取这个快照。AI 失败不能重置它；页面间不可共享。
- 保留 `_display_results(symbols, relations, ai_result)` 既有调用接口。在快照存在时构造轨迹并调用新 `_display_palace_ring(...)`；实际落点详情取 `Prediction.symbols`。对直接调用结果展示但无数字快照的情况，不编造经过路径（可省略新增环），原有卡片仍正常显示。真实提交必须始终有环。
- 正常提交的轨迹落点与 `Prediction.symbols` 一致由测试锁定；不要为画图再调用 `predict`，不要为画图修改预测结果。

### 2. `src/web.py`：组件渲染

- 新增 `_display_palace_ring`，放在输入快照和说明之后、现有三传卡片之前；空状态复用该组件的无轨迹模式，替换旧四字 compass HTML。
- 推荐 NiceGUI 原生 `ui.element`／`ui.label`：相对定位的正方形环容器、九个绝对定位节点，坐标由 `sin/cos` 在服务端生成百分比；DOM 顺序保持 `order` 顺序。使用固定尺寸比例和充分的外围留白，不旋转文字。
- 用新类如 `palace-ring`、`palace-node`、`palace-visit`、`palace-landing`、`palace-summary`，并设置可测试的 `data-order`、`data-stage`、`data-count`、`data-element` 等属性。尽量使用文本控件，若拼 HTML 必须转义领域文本，不插入用户问题。
- 环中央仅放“顺时针／本宫起数”等短说明；不要将三个长摘要挤入环心。落点徽标空间不足时用“初／中／末”并在相邻图例完整解释，保留全部阶段。
- 段摘要显示“初数 n · 从 X 起数 → 初传 Y”等文字与多圈信息；三段元数据摘要在手机上纵排。关系两行允许换行，不要求在圆内绘制交叉箭头。
- 给组件有意义的标题、分组及顺序阅读语义；节点访问标记有可读标签，装饰线 `aria-hidden`，数据环不要整体隐藏于辅助技术。没有交互的节点不设假按钮／多余 tab stop。
- 不移除或改写原有卡片、关系文案和 AI 渲染逻辑；不得将新组件插进 AI 等待／成功容器。

### 3. `src/web.css` 与 `src/themes/{night,ink,neon}.css`

- 在基础文件添加九宫组件布局、节点、三段经过标记、重合落点、图例、段摘要、关系行和元数据样式；新增素纸可读的五行 CSS 变量，颜色规则限定于新组件，保持老卡片默认视觉。
- 复用主题五行变量，三个主题分别补充组件背景／边线／文字／落点强调，所有选择器仍以各自 `html[data-theme="..."]` 开头，符合现有主题测试。素纸金元素用深金／灰褐而非低对比白色；深色主题避免模糊光晕掩盖正文。
- 不复用旧 `.compass` 类，以免受到旋转／扫描装饰及固定尺寸影响；可删除不再引用的 compass 专属规则，但不顺带重做其他组件。
- 容器 `width:100%`、合适的 `max-width`、`aspect-ratio:1` 与 `min-width:0`；针对最窄阅读面板调整留白及节点标记，摘要自适应单列。320/375/390px 屏幕不裁切九宫、节点名或徽标，不产生横向页面滚动。
- 首版静态呈现所有路径，不依赖动画传达结果，不增加 JS 定时器。增加／确认 `prefers-reduced-motion: reduce` 下新组件及其伪元素无动画与过渡，不能隐藏信息；动态切换四主题时配色即时继承。

### 4. `tests/test_web_palace_ring.py`（新增）与必要的既有测试扩充

纯模型测试：
- 九宫 `order` 为 1..9，名称顺序与只读 JSON 相符；明确断言当前 `SYMBOLS` 顺序与排序结果一致，防止未来数据次序变化让显示与核心分叉。
- 独立写死样例，不能仅用新 helper 自己生成期望值：
  - `(1,1,1)`：落点索引 `[0,0,0]`，三个序列都是 `[0]`，三次落大安。
  - `(1,2,3)`：序列 `[0]`、`[0,1]`、`[1,2,3]`；落点大安、留连、赤口。
  - `(9,9,9)`：落点 `[8,7,6]`（天德、桃花、病符），验证跨边界。
  - `(10,10,10)`：均回到大安，每段十次数宫、大安访问两次、一整圈。
  - `(999,999,999)`：落点 `[8,7,6]`，每段访问次数和为 999，110 整圈加 8 余步。
- 对 1..9 的 729 组三数，以及包含 10、18、19、998、999 的边界组合，把显示落点对象／名称与 `HandTechnique.predict` 比较；检查上段末项等于下段首项。保留独立样例，不能只以核心实现互证。
- 元数据直接使用现有字段，含拼音和空亡的“中 (zhōng)”，不按八卦推导或补造数据。

NiceGUI 集成测试（沿用 `Client(ui.page(...), request=None)` 与模型 availability patch）：
- 空状态九节点顺序正确、有起算标记、无虚构落点。
- 实际 `_perform_divination` 后九节点仍唯一，落点及三段经过标记正确，三个元数据摘要包含每个落点的完整字段，关系方向含 `(1,2,3)` 的“被克／金克木”。
- 重合 `(1,1,1)` 仍显示全部三传；999 输入 DOM 大小有界，不能每一步创建节点。
- 数字／时间／汉字三模式均使用转换后快照（已有时间 `2026-09-15 12:00` 为 `8,5,7`、`中国人` 为 `4,8,2` 可复用）；提交后编辑输入不能改变已有环，再次提交替换旧环。
- AI 失败后图、卡片、快照仍在，按钮恢复；用受控异步 mock 等待 AI 时尝试再次提交，确认 `is_running` 阻止第二次计算／清空，结束后恢复。无需真实网络。
- 两个页面控制器快照／图独立；不污染现有主题测试的 `element-badge`／`transmission-card` 查询。
- CSS 测试检查四主题相关钩子和 reduced-motion 规则，复用现有主题隔离测试；CSS 文本测试不能代替实际视觉验收。

## 验证与独立复核门槛

1. 实施前后均运行 `uv run python -m unittest discover -s tests -v`，以退出码判断结果，记录既有失败与本次失败；规划阶段未运行测试，不承诺基线通过。
2. 本地 `uv run src/web.py`，逐一访问 `/?theme=paper`、`night`、`ink`、`neon`，验证桌面与 320/375/390px；覆盖空状态、默认 `(1,2,3)`、全部重合、跨圈和 999。确认无节点重叠遮字、无横向溢出、全部元数据可见、关系可读，切换主题不需要重新占卜。
3. 浏览器模拟 `prefers-reduced-motion: reduce`；确认信息与正常模式相同且新环不运动。实际检查小字号文字对比度和非颜色识别；可保存截图作为证据。若无浏览器能力，明确列为未完成验收，不把静态 CSS 测试当作视觉通过。
4. **必须在实现后委派未参与实现的独立 Agent Reviewer**：虽核心算法不变，本次新增显示路径推导仍属于算法新增。提供本规格、变更范围及上述命令，请其独立构造计数参考样例／性质检查，检查 inclusive counting、九宫顺序、跨圈、同宫三落、三模式快照、关系方向、元数据及旧行为兼容。明确只读文件未变，独立预期不能全部来自实现自身。
5. 将 Reviewer 的范围、独立证据、结论、未解决项与覆盖限制保存在单独审查记录（例如 `docs/specs/d8b3217d_nine-palace-review.md`，写入前确认不存在同名文件）。阻断问题修复后由同一 Reviewer 复查。Reviewer 未完成则不得声明该算法展示已完成。
6. 最后检查 diff：无 `data/`、预测／关系／AI prompt／CLI 改动；全量测试通过、人工验收和独立复核证据齐全再交付。

## 交付验收摘要

- 一次起课始终显示九宫、起算点、三段经过位置与三落点，结果与 `predict` 一致，包括 n=1、多圈及重合。
- 三传五行颜色配文字，两段关系方向与现有解释一致，完整展示手指位置及八卦原始值。
- 四主题与手机尺寸可读，减少动态偏好有效，原有结果／AI／异步行为保持。
- 新增测试和全量 unittest 通过，独立 Reviewer 已给出非阻断结论，并记录视觉验收证据或明确限制。
