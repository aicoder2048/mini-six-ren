# 九宫环三传分色与指针计划

## 目标与范围

为初传／中传／末传分配三个不同的阶段色，使同一传的落点 chip、经过 chip 与新增中心指针共享该色。结果环增加三根钟表式指针，指向各自落宫，并在既有动画到达该传时出现；减少动态偏好下立即显示最终位置。空状态不显示指针。

修改文件限于 `src/web.py`、`src/web.css`、`src/themes/{night,ink,neon}.css`、`tests/test_web_palace_ring.py`。核心预测、关系算法、data/、CLI、AI prompt 及 `theme.js` 不改。九宫坐标、半径、符号标签、起算标记不改。原有结果卡片、五行说明、元数据摘要、关系文字、AI、提交锁及失败保留本地结果行为不变。

本次明确替换的是**环上落点 chip 的五行配色**：它现在表示传次颜色，而非五行。保留 `data-element`、手指／八卦元数据及卡片和摘要中的五行显示，不把阶段色映射到五行，也不顺带修复其他既有视觉问题。

## 已核实的代码现状

- `build_palace_walk` 已提供 `segments[*].landing_index`、`sequence` 和九宫顺序，节点由 `_palace_coordinates(index, count)` 定位，索引 0 在正上方，其余顺时针每 40°。
- `build_palace_animation` 已提供 `landing_ms` 和 `relations_ms`：起算 300ms、每计数 160ms、每落点停留 240ms。`palace_animation_css` 生成九条节点高亮时间线。
- `_display_palace_ring` 每次结果创建 UUID 作用域与子树内 style；chip 通过 `--palace-delay` 揭示。新提交移除旧子树并可靠重播。
- 基础及主题 CSS 存在 `.palace-landing[data-element=...]` 的高优先级配色，以及主题统一颜色的 `.palace-visit` 规则。只给 markup 加阶段类不够，必须移除／替换环上这些冲突规则。
- reduce 已在整个 `.palace-ring-block` 子树禁用 animation／transition；新增指针要以最终可见位置作为基础样式，使该路径自然正确。
- 历史实现审查在 `docs/specs/d8b3217d_palace-animation-review.md`，其中记录了浏览器验收脚本及截图位置；可复用验证方法，但不能用历史证据代替本次验收。

## 设计决定

### 1. 稳定阶段色契约

新增专用阶段键 `initial`、`middle`、`final`，按 `PALACE_STAGES` 次序映射；不要改变现有 `PALACE_STAGES` 二元组结构造成无关调用变更。新增共用类：

- `.palace-stage-initial`
- `.palace-stage-middle`
- `.palace-stage-final`

相同阶段的 `.palace-visit`、`.palace-landing`、`.palace-hand` 都使用同一个类。保留已有中文 `data-stage` 及所有数据属性。阶段类将局部 `--palace-stage-color` 指向环根的三个主题变量（如 `--palace-initial-color` 等）。

chip 的文字／边线用该阶段色，背景用对应浅色／透明底；指针线用同一个原色。避免同一传手与 chip 实际使用两种不相关色值。保留“初／中／末”和完整落点文本，不仅靠颜色识别。原节点逐步高亮色不在本次范围内，不改其时序或颜色。

### 2. 指针几何与重合

- 每根指针从环中心 `(50%,50%)` 出发，最终方位由 `landing_index * 360 / len(walk.palaces)` 确定，0°朝上、正角顺时针；用现有 `PALACE_RADIUS` 派生长度，不添加第二套硬编码宫位坐标。
- 推荐 NiceGUI 原生 HTML div 指针：外层是以环中心为旋转基点的零尺寸 pivot，旋转到目标角；内层是一条向上的线，长度为环半径，末端指向该宫中心。可用覆盖全环的指针层和百分比高度实现，避免依赖零尺寸父节点的百分比高度。用纯 helper 返回目标索引／order／角度，便于测试；不要修改数宫算法。
- 指针位于环装饰之上、节点与中心说明文字之下，`pointer-events:none`，不占布局。中心说明的位置与内容不改；细线不得穿盖文字，可给现有中心说明加与当前面板匹配的遮线底层，但不移动／改字。节点层应遮住线尖，视觉上终止在落宫而不是穿过标签。
- 处理 `(1,1,1)` 等重合：三根线都存在且指向精确同一角度，不偏转目标来凑开。采用阶段固定的线宽和绘制层级（例如初 6px、中 4px、末 2px，由宽到窄叠放），使同向线仍露出各自颜色边缘。允许小端点装饰辅助区分，不改变九宫几何或落点标记布局。手机尺寸也须保留至少可辨认的每色边缘。
- 三根手可以是装饰性 `aria-hidden=true`，因为落点文字已有完整语义；同时暴露测试属性 `data-stage`、`data-target-index`、`data-target-order`，测试不用猜测角度或解析像素。

### 3. 加入既有动画，不重建时间表

选择“到达落点时出现”的明确实现，避免另加一套逐步旋转算法：

- 指针的 delay 直接使用 `animation.landing_ms[stage_index]`，与对应落点 chip 同时开始显示。
- 在该传 240ms 落点停留窗口内，用 180ms 的淡入／从中心沿目标方向伸展完成显现。它始终指向正确落宫，不从正北乱扫整圈，不冒充该段数宫路径。用户要求的 appears/sweeps 以此“到达时出现并伸展”的方式满足。
- 外层负责固定旋转，内层负责 `scaleY(0..1)`／opacity，避免覆盖定位 transform 或造成角度改变。基础内层是 `opacity:1; transform:scaleY(1)`；普通动态模式动画用 backwards fill 隐藏 delay 期间内容，结束自然回到基础终态。
- 之前出现的指针保留；第三根在关系揭示前完成。原逐步高亮、chip reveal、landing／relations delay 和总时长完全不变。
- no-preference 才激活动画；reduce 时三根立即最终可见，无延迟、无伸展、无过渡。播放中切换 reduce 同样立即终态。
- 复用现有新 DOM 重播与子树清理机制。不新增 JS、服务器 sleep、timer 或新的提交锁；主题切换不改变动画名或重建指针。

## 文件级实施步骤

### `src/web.py`

1. 加阶段键映射和必要的纯指针展示 helper（建议只接收 `PalaceWalk`，输出三阶段目标及角度，不改现有 dataclass 公共结构）。目标只来自 `landing_index`，不能重新调用 `predict` 或从标签／UI 值推导。
2. `_display_palace_ring` 的结果分支创建一个指针层与三根 `.palace-hand`，属性包含阶段、目标宫及 delay，CSS 角度变量以度数表示。empty 分支不创建指针层或指针。
3. 给27个经过槽、三枚落点和三根指针各加对应阶段类。未访问槽仍保持隐藏与最终 `data-count`，不更改原父子层级与字段。
4. 保留 `_perform_divination`、`_display_results` 和 `palace_animation_css` 既有业务／时间线；只在环渲染内增加内容，避免影响旧关键帧解析测试。

### `src/web.css`

1. 增加三个阶段颜色变量及阶段类映射；将 chip 共用前景／边框规则改为读取阶段色。删除环落点的五行配色规则及旧经过槽阶段阴影色值，避免覆盖阶段色。五行卡片和摘要规则保持不变。
2. 增加独立指针层、中心旋转 pivot、手的线条与重合层级。环保持原正方形、半径、节点坐标及手机断点尺寸。
3. 添加共享 `palace-hand-reveal` keyframes 与 no-preference 规则，延迟来自已有时间表。可复用 stage 变量，不生成额外动态关键帧，不修改九宫高亮时间线。
4. 确认 reduce 覆盖新增所有层与伪元素，最终位置在基础样式中；不要用统一 `visibility:visible` 破坏未访问槽。

### `src/themes/{night,ink,neon}.css`

1. 各主题 `.palace-ring-block` 覆盖三个阶段色及必要的柔和背景变量。
2. 替换主题内环落点 `[data-element]` 规则和统一色 visit 规则；保留原 chip 的主题圆角／字体风格，但前景、边线和手使用阶段色。不要保留更高 specificity 的旧五行配色压过新规则。
3. 指针可保留各主题细微装饰差异，但不能增加强烈光晕影响辨色。主题新选择器仍以 `html[data-theme="..."]` 开头，通过既有隔离测试。共享伸展 keyframes 即可，不复制时序。

### `tests/test_web_palace_ring.py`

新增并扩展以下断言，保留全部既有路径／时序与业务测试：

- 空状态指针数为 0；每次有效结果恰好3根，分别带 initial/middle/final 类、中文阶段、目标 index/order。九节点、27 槽和3落点数量不变。
- 独立样例 `(1,2,3)`：落点 index `[0,1,3]`，order `[1,2,4]`，向上顺时针角 `[0,40,120]`；`(9,9,9)`／`(999,999,999)` 为 `[8,7,6]` 和 `[320,280,240]`；`(1,1,1)` 和 `(10,10,10)` 三根均0°且不得合并。
- 对既有九宫全组合与边界样例，把手目标符号与 `HandTechnique.predict` 返回的阶段符号比较；增加坐标性质检查，确认角度方向与 `_palace_coordinates` 一致而非镜像。保留上述写死独立期望，不能仅互相调用实现生成期望值。
- 每阶段所有经过 chip、落点 chip 和手携带同一个且唯一的阶段类，三阶段不同。`data-element`、手指／八卦字段仍保持预测事实，且不会影响阶段类。
- 指针 delay 与落点的 `landing_ms` 一致：默认输入为 `[460,1020,1740]ms`；180ms 动画结束均不晚于下段开始／最终关系1980ms。原 node/chip/relations 延迟和动态样式内容保持旧测试通过。
- 扩充连续相同输入提交、AI等待／失败和双客户端测试：重播只保留新3根手，旧层无残留；失败不替换作用域、三手保留；大输入指针仍只有3根，不生成每步指针。
- 样式契约检查四主题分别声明三个不同阶段变量，颜色规则覆盖 visit/landing/hand，reduce 下禁用全部新增动画、基础手为最终可见状态、no-preference 包含手显现规则。不能只断言类存在就宣称颜色／reduce 视觉通过。

## 验证与独立复核

1. 开始前记录基线，运行 `uv run python -m unittest discover -s tests -v`；实施后同命令必须退出0。命令以退出码判断。规划未运行测试，不把历史96项通过视为本次结果。
2. `uv run src/web.py` 实际四主题验收，复用既有浏览器检查方法（旧脚本位于同会话 context_handoff，先核实可用性），不要启动／停止不属于自己的既有服务。桌面及320/390px检查三根手从中心指向正确落宫，空状态无手，起算和节点几何完全不变。
3. 浏览器时间采样：每传 landing 前手不可见，到点开始出现，180ms后终态，前传手仍在；最后关系时间不变。验证自然播放而非只在测试中手工设置终态。
4. 四主题检查 computed style：同阶段 chip 的前景／边线与手线色相同，三个阶段不同；不同五行的同一阶段仍同色，同一五行的不同阶段仍异色。小字号文字需可读（建议至少4.5:1），线与背景有明显对比；保存屏幕截图，不以色值字符串互异代替实际辨识。
5. 特别检查 `(1,1,1)`、两传重合和跨圈落点，三根同向指针仍可辨认，没有被最后一根完全遮住。既有中心说明和符号名不被线遮挡，手机无新增横向滚动。
6. reduce 下提交及播放中切换 reduce：三手立即最终可见，无活动伸展动画，未经过槽仍隐藏。相同输入再次提交重播；主题切换仅配色变、动画不重启；AI失败保留手和图。
7. 本次新增角度／目标展示映射，按 AGENTS.md 的算法新增要求，实施后委派未参与实现的独立 Reviewer。提供本规格、diff和验证命令，要求独立参考样例核对方向、落点、重合、动画时间、减少动态终态、只读文件及业务兼容性。阻断问题修复后由同一Reviewer复查。
8. 将范围、证据、结论、未解决项及覆盖限制写入新审查记录，例如 `docs/specs/d8b3217d_palace-hands-review.md`，先确认路径空闲，不覆写旧动画审查。缺少真实浏览器或独立复核时明确尚未完成，不将静态CSS测试作为完整视觉验收。

## 完成标准

三传各自拥有一致且互异的 chip／手颜色，三手目标与预测落点一致；空状态无手，重复落点仍可区分；既有序列动画与时序不变，每传到达时出现其手，reduce 即时终态；四主题手机可读，核心／数据及原有结果和AI行为无变化；全量测试通过并保存本次浏览器验收与独立复核证据。
