# 九宫环逐步动画计划

## 目标与边界

让现有九宫环在每次成功起课后依次展示：起算 → 初数逐宫经过 → 初传落点 → 中数逐宫经过 → 中传落点 → 末数逐宫经过 → 末传落点 → 两条关系。动画结束后与当前静态环完全一致。减少动态偏好下直接显示静态终态。

本次只修改 `src/web.py`、`src/web.css`、`src/themes/night.css`、`src/themes/ink.css`、`src/themes/neon.css` 和 `tests/test_web_palace_ring.py`。`src/themes/theme.js` 只读参考；不修改 `HandTechnique.predict`、关系算法、data/、CLI、AI prompt。不得调整环几何、已有标签、五行配色终态、元数据或结果卡片布局。

## 当前实现与关键约束

- 已有 `build_palace_walk` 返回三个 `PalaceSegment`，其中 `sequence` 保存完整计数轨迹，长度恰好等于输入数，包含起点与落点；`visit_counts` 仅是聚合结果。动画必须使用 `sequence`，不能只动画去重宫位或将数字误当移动步数。
- `_display_results` 根据 `number_snapshot` 构建轨迹；`_display_palace_ring` 创建九节点、27 个经过槽、三个落点、三个摘要和两段关系文本。空状态复用同一函数但 `walk=None`。
- 每次提交清空结果容器并重建，因此新 DOM 可自然触发 CSS 动画；不需要服务端 sleep、逐帧 websocket 更新、改变 `is_running` 或等待动画后再请求 AI。
- `.palace-node` 本身使用 `translate(-50%, -50%)` 定位，不能用动画覆盖其 transform。未经过槽的 `visibility:hidden` 必须保留。
- 当前 reduce 规则只覆盖 `.palace-ring` 子树，而 `.palace-relations` 在它之外。全局 `animation-duration:0.01ms` 不会消除 animation-delay，不能靠它实现立即完成。
- 现有测试已覆盖路径、输入快照、同宫三落、大输入 DOM 有界、AI 失败、防重入及页面隔离；新增动画不能削弱这些断言。

## 动画契约

### 时间线

采用纯 CSS 播放，服务端只生成一次完整时间表。固定时间常量作为首版：起算单独展示 300ms；每个计数项停留 160ms；每段落点停留 240ms；末传停留结束后两条关系同时出现。所有步骤都播放，不将多圈取模缩短或省略。

- t=0：九个符号、环几何、原有标题与起算可见；经过 chips、三落点及环组件自己的关系区暂时透明。原有三传卡片、卡片关系文本、三个元数据摘要与 AI 面板保持现有显示时机，不纳入隐藏范围。
- 初段从 t=300ms 起遍历 `segments[0].sequence`。每一项独立占 160ms 高亮窗口；该阶段对应宫位的 chip 从首次访问开始永久显示。再访问同一宫也必须重新高亮，不能因 chip 已可见而略过。
- 一段全部计数项播放完，显示该段落点徽标并保留；240ms 后开始下一段。下一段从上一落点本宫重新数第 1 数，即使宫位重复也保留独立的计数事件。
- 第三段落点显示并停留 240ms 后，显示 `.palace-relations` 整区（含箭头文字和说明）。最后所有临时高亮消失，节点颜色、阴影、文字、布局与静态版本相同。
- `n=1` 仍有一个本宫高亮事件，随后落点；`(1,1,1)` 的三枚同宫落点逐个出现，不覆盖。
- 总计数事件数为 `sum(numbers)`，时间为 `300 + 160*sum(numbers) + 3*240` ms。999 输入可能播放约 8 分钟，这是保留每个可辨认步骤的明确取舍；结果卡片和摘要即时可用，允许按原有规则再次提交替换动画。不要偷偷加速到浏览器无法显示每步或丢弃事件来缩短时长。本次不新增播放控制或跳过按钮。

### 不变的终态

所有现有数据节点与最终属性保持原样，包括 `data-count` 的最终聚合值和各落点元数据；动画仅暂时影响透明度与装饰高亮。未经过槽始终隐藏。动画停止后不残留 outline、缩放、光晕或新增文字。空状态完全静态，不挂播放类或时间表。

## 实施步骤

### 1. `src/web.py`：可测的纯动画时间表

新增小型纯 helper，例如 `build_palace_animation(walk)` 与不可变事件结构，不改 `build_palace_walk` 数法。记录：

- 按时间排序的 step 事件：阶段索引／阶段名、段内计数序号、宫索引、开始时间、结束时间。
- 每个 `(stage, palace_index)` 的首次访问时间；每阶段 landing 时间；关系揭示时间；总时长。
- 事件只来自 `segment.sequence`，落点直接用现有 segment 的结果，不再另写取模推导，不重复调用 `predict`。

独立 helper 将时间表转换为有限个 CSS 时间线，便于单元测试验证实际渲染消费的是同一张时间表。不要将用户问题、数据文本或未经约束的值拼入 CSS；仅输出数字和程序生成的安全标识符。

### 2. `src/web.py`：给已有 DOM 添加播放钩子

- 在 `walk is not None` 的环外层增加专用播放类和每次渲染唯一的安全标识（可用 NiceGUI 元素 id 派生，确保不同页面／提交不冲突）。保留原有父子层级，尤其是 `.palace-landing` 直接属于 `.palace-node` 的测试契约。
- 给有访问的 chip 设置首次访问的 CSS delay；给三枚落点设置对应 landing delay；给 `.palace-relations` 设置最终 delay。默认基础样式为完整可见终态，只有普通动态偏好下的播放类激活动画。用 `opacity` 隐藏而不是 `display:none`，确保布局／节点高度从开始到结束不跳动。
- 起算从首帧可见，其他标记有严格更晚的揭示时间，满足“起算先出现”；无需使起算徽标本身闪烁。
- 为九个节点各生成一条独立高亮时间线：在其被访问的 step 窗口亮起，在其他窗口关闭。推荐使用节点的绝对定位伪元素作轻量 outline／背景强调，只动画伪元素 opacity，不改节点 transform、尺寸、文字或最终 box-shadow。最多九条高亮动画，CSS keyframe 数量随步数增加，DOM 节点数不随步数增加。
- 关键帧采用离散切换（`steps(1, end)` 等），不会跨宫补间或提前亮起。百分比保留足够精度（至少六位小数），包括 0% 和 100% 关闭状态；段间停留高亮关闭。重复访问和相邻窗口应精确对应时间表，不产生跨段提前点亮。
- 每次结果渲染的一份动态 `<style>` 随环容器挂载，并在容器 clear 时一起移除。使用项目当前 NiceGUI 支持的原生 style 元素或 HTML style 承载方式；先核实 API 与浏览器实际注入，不依赖会过滤 style 的默认 sanitization。不使用每次提交 `ui.add_head_html`／全局 `ui.add_css` 累积旧关键帧。
- 唯一 keyframe 名和 root 作用域保证提交相同数字也重播；旧环被移除后旧动画自动消亡。无需额外客户端运行时、计时器、MutationObserver 或改动 `theme.js`。
- 不改 `_perform_divination` 的时序、异常处理或锁；AI 成功／失败只更新现有 AI 区，不触碰环播放类。动画中再次提交（在原锁允许时）直接移除旧环并开始新环。

### 3. `src/web.css`：默认终态与通用播放样式

- 保留所有现有静态规则。增加通用 reveal keyframes：从透明到不透明，延迟期间通过 backwards fill 保持透明，播放后恢复基础可见样式；不为节点设置永久隐藏默认值。
- 所有播放规则限定为 `.palace-ring-block` 的专用播放类，放在 `@media (prefers-reduced-motion: no-preference)` 下。空状态不带播放类。
- 新增节点伪元素装饰的绝对定位、高亮色变量、`pointer-events:none`、默认 `opacity:0`。不新增读屏内容，不设置逐步 aria-live 播报，保留原静态文本可访问性。
- reduce 规则扩展到整个 `.palace-ring-block`、后代和伪元素，包括关系区：`animation:none !important; transition:none !important`，清除延迟影响，保证正常数据项立即可见、装饰关闭。不能用通用 `visibility:visible` 覆盖未经过槽的隐藏规则。
- 在播放中切换到 reduce 应立刻到终态；无需 JS 监听，媒体查询负责生效。减少动态模式下没有等待 landing delay 的隐藏残留。

### 4. `src/themes/{night,ink,neon}.css`：只改变临时高亮皮肤

- 素纸的临时高亮使用暖朱砂，星夜使用金色，水墨使用墨／朱边框，霓虹使用现有青色轻光晕；通过作用域内 CSS 变量或伪元素样式实现，共用同一时间表及关键帧，不复制四套时间逻辑。
- 所有新选择器遵守现有 `html[data-theme="..."]` 前缀约定；如增加主题专用 keyframes 必须以主题名开头，但优先共享 opacity 时间线，仅主题化装饰。
- 不触碰既有落点／chip／元数据终态规则。主题切换只改变临时高亮颜色，不更换 animation-name 或重新启动整段时间线。不改变主题原有其他动画。

### 5. `tests/test_web_palace_ring.py`：扩展而不是替换旧测试

纯时间表测试：
- `(1,2,3)` 完整 step 序列必须是 `(初,0)、(中,0)、(中,1)、(末,1)、(末,2)、(末,3)`，共 6 步。写死独立时间：首步 300ms，初传 460ms，中段首步 700ms、中传 1020ms，末段首步 1260ms、末传 1740ms、关系 1980ms。
- `(1,1,1)` 有三步三 landing，均宫索引 0，事件没有去重且各段严格有序。
- `(10,1,1)` 首段为 `0..8,0`，访问大安两次仍有两个窗口；chip 在首次访问揭示、初传直到第十次计数结束才揭示。
- `(9,9,9)`、`(999,999,999)` 检查步数 27／2997、跨边界顺序、最终落点 `[8,7,6]`；每段最后事件与 `HandTechnique.predict` 落点一致，保留既有 729 组对照。
- 所有时间非负、step 时间递增／无阶段交错、每段 landing 晚于末步起点、下段晚于前 landing、关系晚于末 landing。每个实际访问 chip 的 delay 等于对应首次 step 起点。
- 测试 CSS 时间线生成器：每个宫的 on/off 窗口与 step 表一致，重复访问未丢失，末尾回到关闭，不只测试一个未被渲染使用的 helper。

NiceGUI 集成测试：
- 成功提交的 root 带新播放作用域及动态样式，起算无长延迟，chip／landing／relations 的延迟与模型一致；空状态无动画作用域。
- 相同数字连续提交获得新的播放标识／动画名；结果区域只保留当前一份动态样式、九节点／27 槽／三落点，旧样式不积累进 head。
- 999 输入 DOM 数量仍有界；样式可变长但不创建 2997 个高亮节点。
- 保留所有原有元数据、卡片、关系文案断言；扩展现有 AI failure 测试，检查等待 AI、防重入与失败后同一动画作用域未被重建。页面间作用域独立。

reduce 与样式测试：
- 将现有仅检查 `.palace-ring` 字符串的弱测试扩充为：普通动画受 no-preference 限定；reduce 覆盖整块及关系／伪元素、禁用 animation 和 transition；基础終态可见，未访问槽仍隐藏。验证四主题的高亮钩子，继续通过 `test_web_themes` 的主题选择器隔离测试。
- Python DOM／CSS 文本测试不能证明浏览器真的执行动画；下面的真实浏览器检查是必需的验收证据。若已有浏览器测试设施可用，可把关键时间采样自动化，但不为此新增运行时依赖或让全量 unittest 依赖网络。

## 验证与验收

1. 实施前后运行 `uv run python -m unittest discover -s tests -v`，以退出码判断，不根据输出文字推断成功。规划阶段没有执行测试，基线未验证。
2. 运行 `uv run src/web.py`，在 `/?theme=paper`、`night`、`ink`、`neon` 逐一实际提交 `(1,2,3)`：确认起算先显示，逐宫高亮和 chips 揭示正确，三 landing 分阶段出现，最后关系出现；已有卡片和 AI 区不等待动画。
3. 检查 `(1,1,1)`、`(10,1,1)`、日期和汉字输入，尤其跨圈再访问、同宫三落和本宫起数。999 的完整 step 数由测试保证；浏览器检查首段连续播放及 DOM 不爆增，可用浏览器动画时间控制快进到终点检查最终状态，不能据跳帧视觉推断步数。
4. 相同输入重新提交应从起算重播；在旧动画尚未结束时提交新输入，不残留旧高亮；切换主题不使时间线从头开始。AI 等待／失败不清空环，不阻塞既有提交流程。
5. 浏览器模拟 `prefers-reduced-motion: reduce` 后提交，首个渲染帧即见全部最终 chips、落点、关系且无高亮运动；处理中切换偏好也立即终态。使用 computed style 确认延迟没让内容继续隐藏、未经过槽仍隐藏。四主题均验证。
6. 在桌面、320px 和390px 检查装饰不改变节点位置、文字可读、无新增横向滚动。对同一输入分别截取旧静态版本、动画终点与 reduce 模式，比较几何、标签和最终外观相同，确认未改原有静态问题。
7. 新增时间表属于展示算法新增，按 AGENTS.md 要求委派**未参与实现的独立 Reviewer**。提供本规格、改动范围、测试命令，要求独立检查 inclusive counting、重复访问／跨圈、时序、CSS 百分比精度、reduce 终态、重播和旧行为兼容。修复阻断问题后由同一 Reviewer 复查；未完成不得宣称完成。
8. 审查证据（范围、独立参考样例、命令退出码、浏览器结果、结论及限制）保存到独立记录，例如 `docs/specs/d8b3217d_palace-animation-review.md`，先确认名称空闲再创建，不覆写历史记录。无浏览器或独立 Reviewer 能力时明确记录验收尚未完成。

## 交付完成标准

所有起课模式均按完整轨迹依次播放并回到原静态终态；四主题、手机布局与 reduce 路径验证通过；每次提交可靠重播；核心算法、只读文件及业务异步行为不变；全量 unittest 与新增时序测试通过，独立审查及浏览器验收有证据。
