# 功能与体验改进提案（待确认）

状态：提案，尚未实现，也未拆分为 ticket。本文只记录候选范围与验收思路，供确认后再用 `to-spec` / `to-tickets` 转为正式规格。
基线：`master`（本文写作时 HEAD 为 `de86b26`）。
范围说明：下列三项均**不改变占卜算法、历法、五行关系或 AI Prompt 事实**，因此不触发 `AGENTS.md` 的独立算法复核；仅涉及界面、入口与导出。若后续实现范围扩大到计算层，需另行安排独立 Reviewer。

## 背景

现有系统已经完成基础修复与体验改进（见 [review-improvements](review-improvements.md)、[interpretation-experience](interpretation-experience.md)、[prompt-quality](prompt-quality.md)）：本地三传与五行关系无需密钥即可计算（`HandTechnique.predict` 返回 `Prediction(symbols, relations)`，与界面解耦），CLI 与 Web 共用校验和历法转换，Web 已有四套皮肤与响应式布局。

当前的主要空白不在算法，而在「**使用与留存**」：

- 起课结果只存在于当前页面/终端会话中，用户想保留或分享只能手工截图或抄写；
- CLI 只有菜单交互，无法被脚本、CI 或其它程序直接调用，尽管本地计算本身是纯函数；
- Web 的皮肤选择已用 URL 参数（`?theme=night`），但**起课输入本身没有可复现链接**，分享结果需要对方重新手输。

以下三项针对这些空白，优先做低风险、不触碰计算层的工作。

## 提案 1：Web 结果一键复制 / 导出（优先级：高）

### 动机
结果卡片已包含完整结构化信息（输入快照、三传、五行、关系方向、本地释义、可选 AI 解读），但只能整页截图。对想留存或发给朋友核对的人，缺少一个规范的文本出口。

### 方案
在结果区块（`DivinationWebApp._display_results` / `_display_ai_result` 附近）增加两个纯前端动作，**不新增后端接口、不调用算法**：

- **复制文本**：把输入快照、三传（符号 / 五行 / 释义）、两段关系方向、可选 AI 解读拼成 Markdown 文本，写入剪贴板，并给出「已复制」反馈。
- **下载 Markdown**：同上文本导出为 `.md`（或 `.txt`）文件，文件名带日期，例如 `小六壬_2026-09-17.md`。

数据来源直接使用 `self.divination_result.symbols` / `.relations` 与现有的 `describe_relation(...)`，保证与页面显示一致；无 AI 解读时也能导出本地部分。

### 涉及文件
- `src/web.py`：新增导出函数与按钮，复用已渲染的 `symbols`/`relations`/`input_summary`。
- `src/web.css` / `src/themes/*`：导出按钮样式，需兼容四套皮肤。
- `tests/`：新增测试，断言导出文本包含三传名称、五行与关系方向。

### 验收标准
- 三种输入模式（数字 / 日期 / 汉字）起课后均可复制与下载。
- 导出内容与页面显示一致：含输入快照、三传、两段关系及其方向说明、本地释义。
- 无 API 密钥、未填问题时导出仍成功（只含本地结果）。
- 浅色与深色皮肤下按钮可读、可点击；不影响既有提交/等待/失败状态逻辑。

### 非目标
不做图片渲染、不做云端上传、不记录用户自由文本问题到任何持久存储。

## 提案 2：CLI 非交互 / 可脚本化调用（优先级：中高）

### 动机
本地三传是无副作用纯计算，但 CLI 目前只能进菜单逐级选择，无法用于脚本、批处理或自动化验证。给开发者和其他程序一个稳定入口，成本低、收益明确。

### 方案
保留现有交互菜单为默认行为，新增可选的命令行参数入口（`argparse`）：

- `uv run src/cli.py --numbers 1,2,3`：直接计算并打印与 `format_prediction` 一致的文本。
- `--date 2026-09-17 --time 14:00`：走共享的 `date_to_numbers`。
- `--chars 天地人`：走 `validate_chinese` + 笔画字典。
- `--json`：输出结构化结果（符号名、五行、关系、方向说明），便于程序消费。

交互模式保持不变；参数缺省时仍进入原有菜单。AI 不参与非交互路径，避免在脚本里意外发起付费请求。

### 涉及文件
- `src/cli.py`：参数解析与入口分流，复用 `format_prediction`、`validate_*`、`date_to_numbers`。
- `tests/`：覆盖参数解析、退出码、`--json` 结构，以及非法输入报错。
- `README.md`：补充非交互用法示例。

### 验收标准
- `--numbers 1,2,3` 输出大安、留连、赤口，关系为比和、被克（与 README 记录一致）。
- 成功退出码 0；非法参数（越界数字、错误日期、非汉字）返回非 0 并打印清晰错误。
- `--json` 输出可被 `json.loads` 解析，字段与 `Prediction` 一致。
- 不带参数运行仍进入原有交互菜单，不改变现有 CLI 测试。

### 非目标
不引入日志/历史/配置文件；网络请求与 AI 不进入本路径；不替换 Rich 菜单。

## 提案 3：可复现起课链接（优先级：中）

### 动机
皮肤已经通过 URL 参数记忆（`?theme=`），但真正需要分享的是**结果**。当前分享只能让对方重输入。把输入编码进链接即可「打开即复现」，且完全复用现有本地计算。

### 方案
在 Web 读取查询参数，预填输入并可选自动起课：

- 数字：`?mode=numbers&n=1-2-3`
- 日期：`?mode=date&d=2026-09-17&t=14:00`（按项目约定解释为北京时间 UTC+8）
- 汉字：`?mode=chars&c=天地人`

在结果区增加「复制结果链接」按钮，生成上述链接。**用户自由填写的问题不写入链接**，以保护隐私；AI 解读同样不入链接（需要密钥，无法保证对方可用）。参数非法时回退到默认空表单并给出提示，不影响页面可用性。

### 涉及文件
- `src/web.py`：读取 `ui.context` / query 参数、预填与自动起课、复制链接按钮。
- `tests/`：对合法参数、非法参数回退、三种模式分别断言起课数字与页面显示一致。
- `README.md`：说明链接参数与隐私约定。

### 验收标准
- 用带参链接打开页面，得到与生成时相同的三传与关系。
- 非法 / 缺字段参数回退到默认状态并有提示，不抛异常、不白屏。
- 链接中不含用户问题文本与 AI 解读。
- `?theme=` 与既有的输入参数可同时生效。

### 非目标
不引入服务端存储或短链服务；不导出 AI 解读；不改变每次请求创建独立 `DivinationWebApp` 的隔离约定。

## 暂不在本轮范围

以下方向有价值，但成本或风险更高，建议单独立项，不与上述三项混做：

- **本地占卜历史**（`localStorage` 记录最近数次起课）：涉及隐私与清除策略，需先定规格。
- **八字「日主分析」遗留的农历月映射**：已在既有规格中标记为已知遗留问题，属算法范围，需独立复核。
- **真实模型在线人工评测**：`docs/evals/three-transmissions.md` 已有固定场景与评分标准，但仍缺真实 A/B 结果，属评测而非功能开发。
- **未使用数据清理**（`bagua.py`、`celestial_stems_earthly_branches.py`、`data/太岁_*.json`）：属重构，收益不确定，暂缓。

## 建议推进方式

1. 先确认本文范围与优先级；仅选择其中一项或两项进入 `to-spec`。
2. 用 `to-tickets` 拆为可独立验收的 ticket，写入本地 tracker。
3. 实现后按 `docs/agents/workflow.md` 做 Standards / Spec 双轴审查；因不涉及算法，无需独立算法 Reviewer。
