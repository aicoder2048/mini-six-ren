## 2. 明确领域决策

### 年份与资料缺失

1. API 固定为 `analyze_tai_sui(birth_year_branch: str, target_year: int | None = None) -> dict`。
2. 出生支只接受十二地支中的单个字符；调用方传 `calculate_bazi(...)['year'][1]`，不得按出生公历年份重新推算生肖。保持原有立春年柱、sect 2 午夜换日规则不变。
3. `target_year=None` 在每次调用时读取 `datetime.now(timezone(timedelta(hours=8))).year`；不得用主机当地时区、UTC 年份或导入时缓存年份。显式年份接受 1900–2099 的整数，拒绝 bool、字符串、浮点及越界值，抛清晰 `ValueError`。
4. 流年是目标公历年份标签，使用既有 `get_chinese_year(target_year)`，例如 `2023 -> 癸卯[兔]`。公历年在北京时间元旦切换，不另行引入立春或春节切换；报告注明「按北京时间公历年」以区分出生年柱规则。
5. 从目标流年支对应的数据文件查找 `年份` 中精确的 `干支 + 年`；列表是稀疏字典，不能按下标、模运算或首项选将军。
6. `申猴` 只有庚申、壬申、甲申、丙申；`酉鸡` 只有辛酉、癸酉、乙酉、丁酉。2028 戊申、2029 己酉没有值年将军记录：正常返回关系结果，`general=None`，`general_description=None`，`general_status='missing'`，界面明确显示「数据未收录戊申年值年太岁」等。不得杜撰、借用其他年资料，亦不得因合法缺项令整份报告失败。用户所述短年份缺失指完整干支记录缺失，不是整个地支文件不存在。

### 关系匹配规则（必须测试并独立复核）

使用目标流年支对应的文件，不反向查询出生支文件，不拼接两个文件的解释。按以下规则基于每个条目的 `地支` 数组匹配，而不是解析 `组合` 字符串或编写传统关系对照表：

- 本次犯太岁范围：`值太岁`、`冲太岁`、`刑太岁`、`害太岁`、`破太岁`；合太岁范围：`六合太岁`、`三合太岁`、`相生太岁`、`得助太岁`。
- 数据另有 `相克太岁`，加载时保留，当前分析不计入也不显示；这是明确的需求范围限制，不是漏读或把它改名为冲太岁。
- 出生支不等于流年支时，仅当二者都在条目 `地支` 中才命中。三合条目按二者共同属于该三合组报告资料关系，不声称完整命盘已形成三合局。
- 出生支等于流年支时，仅命中只包含该支的值/刑条目（对 `地支` 去重判断单支）。因此 `[卯]` 与 `[卯, 卯]` 均可表达自身关系，不能因为出生支等于流年支就命中该文件所有两支/三支组合。
- 条目不包含流年支时不命中。例如丑文件的相生条目 `['酉', '子']`、`['子', '寅']` 是间接背景说明，不等同于用户与流年的直接关系。
- 所有命中条目均保留，包含同类中的多条及同时犯、合；不用 `elif` 短路、不按关系名去重。顺序为上述犯类别、合类别顺序，各类别内部保持 JSON 顺序。
- `类型`（如自刑、相刑）、`组合`、`解释` 原文保留。不得修正数据中与其他传统资料不一致的观点；这是一项资料驱动展示功能，不是资料考据修订。
- 两组都为空才是「无特殊关系」；同时存在时摘要为「犯太岁、合太岁」，不能互相抵消。

## 3. 模块与输出契约

### 新建 `src/utils/tai_sui.py`

实现带 `@classmethod` 的 `TaiSuiData.load_all(data_dir: Path | None = None)`；可另设类方法解析单文件以方便临时目录单测。默认目录是 `Path(__file__).resolve().parents[2] / 'data'`。模块底部仅调用一次，建立 `TAI_SUI_DATA`，正常分析不再触碰磁盘。

- 用既有十二地支与生肖常量生成预期文件名，保证缺少某一文件也会报错；同时发现并处理 `太岁_*.json`，不静默忽略坏文件或重复支记录。不得手写关系表。
- 丑牛、午马、寅虎、巳蛇顶层为文件名生肖标签，其他八份为 `太岁`；接受并统一为以单地支为键的记录。
- 规范化 `年份` 为完整干支年标签到将军/说明的映射；关系类别的对象与对象列表统一为列表。卯兔合太岁只提供六合、三合，未提供相生/得助应自然视为空；不要求每份包含全部可选类别。
- 校验依赖的结构：顶层记录、年份列表、年标签及同文件支一致、神煞两项字符串、关系对象/列表、有效非空地支列表、解释/组合字符串及可选类型。拒绝重复年份或重复支文件以免静默覆盖。
- 校验形状不校正内容：原数据存在不属于六十甲子的干支组合，不因阴阳搭配不合法而拒绝整个文件。
- 读取失败、编码错误、JSON 解析失败、必要结构异常均抛带完整文件名及原因的 `TaiSuiDataError`（建议继承 `RuntimeError`），保留异常链；禁止 `except: continue`。缺少预期文件亦点名该路径；合法的短年份列表不是异常。
- 每次分析构造独立返回值，不让调用者修改结果污染模块缓存。

结构化返回固定字段：

```text
{
  target_year: int,
  chinese_year: str,                 # 如 癸卯[兔]
  target_year_branch: str,
  birth_year_branch: str,
  source_file: str,                  # 如 太岁_卯兔.json
  general: str | None,
  general_description: str | None,
  general_status: 'available' | 'missing',
  fan_tai_sui: list[Relation],
  he_tai_sui: list[Relation],
  summary: '犯太岁' | '合太岁' | '犯太岁、合太岁' | '无特殊关系'
}
Relation = {
  relation_type: str,                 # 如 刑太岁、六合太岁
  subtype: str | None,                # JSON 类型
  combination: str,                  # JSON 组合
  branches: list[str],                # 保留原数组
  explanation: str                   # JSON 解释原文
}
```

### B. 新建 `tests/test_tai_sui.py`

使用现有 `unittest`、`unittest.mock.patch`、临时目录、`sys.path` 加 src 的风格，不增加依赖。

1. 加载测试：十二支完整，两种顶层形状（四个生肖键全部遍历）、dict/list 关系归一、重复地支自刑、卯兔缺可选类别、申酉短列表；从非项目工作目录导入也成功。
2. 失败测试：缺文件、不可读文件（mock `PermissionError`，避免权限环境差异）、非法 UTF-8/JSON、缺必要字段/错误字段类型，均断言异常中包含实际文件名。通过临时副本测试，不修改真实数据。
3. 缓存测试：导入后 mock 模块使用的文件打开方法为失败，连续多次分析仍成功；修改返回对象不影响下一次调用。
4. 固定参考案例（期望必须从 JSON 人工核对后作为常量写入，不用被测分析函数计算期望）：
   - `('卯', 2023)`：癸卯，`陈大将军`；将军说明为「癸卯年值年太岁神煞，象征稳健和耐力，提醒一年中的稳定和持续发展。」；犯关系恰为值太岁和刑太岁/自刑，不误报卯酉冲或六合。
   - `('酉', 2023)`：冲太岁与破太岁均保留，不显示额外相克太岁。冲解释为「卯（兔）与酉（鸡）相冲，木金相克，通常代表冲突和竞争。」；破解释为「卯（兔）与酉（鸡）相破，木金相克，表示该年可能会出现突如其来的变化或意外事件，需保持警惕。」
   - `('戌', 2023)`：六合太岁，组合卯戌合，解释「卯（兔）和戌（狗）相合，木土虽有相克但也有相生之象，可能带来复杂的局面。」
   - `('寅', 2023)`：两组空、无特殊关系，仍显示将军资料。
   - `('申', 2028)`：戊申，年份未收录、将军及说明为 None；值太岁仍须正常命中。另测试 `('酉', 2029)` 己酉同样缺将军；2028/2029 不能错误取短列表其他将军。
   - `('巳', 2021)`：辛丑，`彭基大将军`；犯包含破太岁，合包含三合太岁、相生太岁、得助太岁，同时保留解释；相克太岁不纳入。从丑文件逐条固定完整期望列表。
   - `('寅', 2021)`：不得因丑文件间接相生的 `子寅` 或 `寅巳` 报告直接合太岁。
   - 加一个申/酉有记录年份（如 2016 丙申为张飞大将军），验证短列表也能精确查到资料。
5. 默认年份：mock 模块 datetime 时钟，独立用 UTC 瞬间 `2025-12-31 15:59:59+00:00` 与 `16:00:00+00:00` 验证目标分别 2025、2026；让替身真正对传入 timezone 作转换并断言 UTC+8，不能简单让无时区 now 也返回同样年份。显式年份应完全不调用时钟。
6. 输入边界：1900、2099 有效；越界、bool、浮点、字符串年份以及生肖名/完整年柱/多字符/非地支输入均失败。
7. 格式化与 CLI：原六位置参数仍可调用；新 `tai_sui_info` 正确；注入固定年份分析，检查标题、将军说明、每条关系及解释、无关系、缺年份提示均完整出现且顺序稳定。mock Prompt 直接调用 `bazi_calculation`，不需要人工菜单或 AI 凭据。
8. 回归：旧字典三键等值，CLI 移除新增节后与基线逐字一致；原测试套件继续保障八字、历法、日主、小六壬以及 AI/Web 行为。不得改旧测试期望来掩盖旧输出变化。
